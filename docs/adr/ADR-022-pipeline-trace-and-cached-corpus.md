# ADR-022 — Pipeline trace, and a cached demo corpus

**Status:** Accepted
**Date:** 2026-08-08
**Extends §5.1.3 (meta.json) and §5.2.3 (SSE events). No existing decision is reversed.**

## Context

Two gaps surfaced when building a demonstrable artifact.

**1. The pipeline was not traceable.** PROC-08 makes the *score* traceable — every
deduction cites a `file:line`. Nothing equivalent existed for the analysis itself. The
whole progress contract was `Callable[[str, int, int], None]`: a phase name and a counter.
A reviewer asking "what did it check before it made a network call?" had no answer in any
artifact.

This matters more than it first appears, because **the strongest claims in this project are
negative**: nothing is executed, symlinks are never followed, ambiguous callees are never
guessed, the clone is always deleted. A negative claim is invisible unless the thing that
did not happen is counted.

**2. A live demo has two single points of failure** neither of which is under our control:
network reachability, and GitHub's 60-requests-per-hour unauthenticated API limit. Both
fail during a presentation, and there is nothing to fall back to.

## Decision

### Pipeline trace

Nine steps — validate, resolve, clone, walk, parse, graph, score, render, cleanup — each
emitting a `StepRecord` with labelled `StepEvidence`. Written to `meta.json` and streamed
over SSE. `quanta analyze --trace` prints the same records, so the CLI and the web UI
cannot diverge.

Two supporting counters were added because the evidence did not exist: `WalkResult` now
records `files_considered` / `symlinks_skipped` / `dirs_pruned`, and `build_cdg` fills an
optional `ResolutionStats` with `callees_resolved` / `callees_ambiguous` /
`callees_unresolved`. The latter turns RR-2's "static analysis under-reports" from a
caveat into a published number — on PyJWT, 290 callees resolved of 2,435 seen.

**Placement is load-bearing.** Steps carry durations, so the trace lives in `meta.json`
only. A duration inside `cdg.json` or `score.json` would break NFR-03 byte-identical
reproducibility on the very next run. `ResolutionStats` is an out-parameter rather than
part of `build_cdg`'s return value for the same reason — instrumentation must not alter an
artifact. `tests/unit/test_trace.py` re-asserts the three-run determinism guarantee.

### Cached corpus

Pre-computed artifacts for three contrasting public repositories live in `demo/corpus/`,
regenerated by `scripts/build_demo_corpus.py`:

| Repository | Score | Sites | Why it is in the set |
|---|---|---|---|
| `pallets/click` | 100.0 | 0 | No cryptography — 100 is the *correct* answer, not a flattering one |
| `mpdavis/python-jose` | 30.6 | 10 | Middle of the range |
| `jpadilla/pyjwt` | 13.8 | 27 | Cryptography reached directly from many modules |

Each carries the full provenance triple, so a cached example is **reproducible**: anyone
can clone at the pinned SHA and re-derive the numbers.

Cached runs are flagged `cached: true` in the API, badged in the UI and labelled in the
result header. Passing a replay off as a live analysis would be exactly the quiet overclaim
§1.4 exists to prevent.

## Consequences

- The demo works offline, instantly, and identically every time.
- `meta.json` grows by roughly 3 KB per analysis. `cdg.json` and `score.json` are untouched.
- ~1.4 MB of committed artifacts. Acceptable; `cdg.json` for a large repository dominates.
- The corpus goes stale as those repositories move. It is a demonstration aid, not the
  frozen benchmark of M1 — no research claim rests on it, and the pinned SHAs make its age
  self-evident.

## Revisit trigger

The frozen benchmark corpus (M1) exists — at which point the demo should draw from it
instead, and this ad-hoc set retires.
