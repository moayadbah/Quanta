Cryptographic agility measurement for Python repositories

The one thing to know

The analysis tier never executes your code.

pip install runs arbitrary build-backend code before any test does, and Python cannot be sandboxed in-process. So the system splits into two planes with a hard trust boundary. Your repository is parsed, never run — the dangerous half of the pipeline was never deployed here.

Analysis Plane this service
  • Input: any public repository — untrusted
  • Executes target code: never
  • Credentials present: none
  • Clone deleted unconditionally
Research Plane offline, not deployed
  • Input: 12 hand-vetted forks
  • Executes target code: yes, in hardened containers
  • Runs the migration engines and verification
  • Never reachable from this service

What the score means

A 0–100 measure of how hard it is to replace a cryptographic algorithm in this codebase, from four factors with pre-registered weights.

Call sites0.30how many edits
Isolation layer0.30is there a facade?
Algorithm selection0.20config or hard-coded
Propagation depth0.20blast radius
